# 05 — The Remote Access Tier (drafted 2026-07-31)

**Thesis:** mainstream users will not drive Cortland from a terminal on the Mac.
They live in the Claude, ChatGPT, and Gemini apps — phone, desktop, web (field
verdict, 2026-07-31, from the suite's first real phone session). Desktop apps can
launch our stdio servers today and are already served. Phone apps and the web
cannot: those clients run in the vendor's cloud and reach tools by fetching a
**remote MCP server over HTTPS**. Cortland's data and capabilities are
irreducibly Mac-side — the AppleScript bridge to Mail, the context store, the
audit ledger. The remote tier is the bridge: the same governed servers, exposed
deliberately, with the contract intact.

**The one-sentence design:** the transport changes; the contract does not.

## What is already true (and stays true)

| Client surface | Transport | Approval UX | Status |
|---|---|---|---|
| Claude Code / Claude Desktop (Mac) | stdio, local | elicitation card → dialog (auto ladder) | **works today** |
| Any desktop MCP client on the Mac | stdio, local | auto ladder | works today |
| Claude / ChatGPT / Gemini phone apps & web | streamable HTTP from vendor cloud | elicitation where rendered; folder channel as fallback | **this tier** |
| Human with no client at all | — | folder channel (iCloud file move) | works today |

A cloud client's requests originate from the vendor's servers, not the phone.
Private-network reachability (LAN, plain tailnet) is therefore NOT sufficient
for the phone/web apps: the endpoint must be publicly reachable HTTPS. That
single fact drives most of the security design below.

## Exposure ladder (each rung is an explicit human step)

0. **stdio only** — today's default. Nothing listens on any port.
1. **Loopback HTTP** — `cortland remote serve` binds 127.0.0.1 only. Useful
   for local HTTP clients and testing. No auth required beyond the OS user.
2. **Tailnet** — the loopback port shared over Tailscale to the user's own
   devices/agents. Private, end-to-end, no public exposure. Bearer token
   required from this rung up.
3. **Public HTTPS** — Tailscale Funnel or Cloudflare Tunnel terminates TLS and
   forwards to the loopback port. Required for claude.ai / ChatGPT / Gemini
   connectors. OAuth required at this rung (bearer token alone is not
   acceptable on a public URL; see Auth).

Doctrine mapping: **live mode is to writes what the exposure rung is to
reachability** — off by default, each step opt-in, every error resolving
downward. A config parse failure at rung N serves rung 0 (refuses to listen).

## Architecture

One new package: **@cortland/remote** — a gateway process, not a rewrite.

- Mounts the existing governed servers (mail, context) under one origin:
  `/mcp/mail`, `/mcp/context`. They keep their own identities, tool sets, and
  the shared audit DB. Zero changes to @cortland/mail or /context.
- MCP **streamable HTTP** transport from the official SDK, one session per
  client, Origin-header validation on (the spec's DNS-rebinding defense),
  loopback bind ONLY — public reachability is always a tunnel's job, never a
  `0.0.0.0` bind.
- Every HTTP request annotates the audit trail: principal (token id / OAuth
  subject), origin, session id. The audit row for a remote gated write shows
  WHO asked from WHERE alongside the existing what/when/outcome.
- launchd template + `cortland remote on|off|status`. `off` is the kill
  switch: unload the agent, close the port, revoke nothing silently.

## Auth

- **Rungs 1–2: bearer token.** Generated by the wizard (`openssl rand` class),
  stored in the macOS Keychain (never in config files — house rule), shown
  once. Constant-time comparison, per-token id in every audit row, revocation
  = delete from Keychain.
- **Rung 3: OAuth 2.1** per the MCP authorization spec — the connector flows
  of claude.ai and ChatGPT require it (dynamic client registration + PKCE).
  This is the largest single work item in the tier and lands as its own
  milestone. Until it lands, rung 3 is possible-but-discouraged with a long
  random path + bearer token, clearly labeled as the interim.
- **Scopes at mint time: `read` or `read+write`.** A read token cannot invoke
  gated tools at all (denied before the gate, audited). Default mint is read.

## Why a stolen token still can't send mail

The property that makes this tier defensible at all: **the approval gate is a
second factor that does not travel with the token.** A write-scoped token gets
an attacker exactly one thing — the ability to ASK. The action still dry-runs
unless live mode is on, and still requires human approval through a channel the
token holder does not control (elicitation to the real user's client, the
dialog on the real user's Mac, the file in the real user's iCloud). The
attacker's request becomes a notification to the victim describing the attack.
Every deny is an audit row with the token id attached.

Residual risks, named honestly:
- **Read scope is real exposure.** Mail headers, search, thread content —
  fenced and audited, but readable. Minting read tokens is a serious act; the
  wizard says so at mint time.
- **Approval fatigue.** If remote use normalizes tapping Approve, the gate
  weakens socially. Mitigation: the approval card always names tool, scope,
  and a redacted summary — never "OK?".
- **Tunnel provider trust.** Funnel/Cloudflare terminate TLS. Acceptable for
  v1 (they already carry the world's traffic); self-hosted TLS is a rung-3
  option for the paranoid, not a default.

## Approval UX over remote clients

Elicitation is transport-agnostic — the card carries over wherever the vendor
renders it. The matrix as of 2026-07-31 (NOTES Q26): Claude Code CLI renders it
(2.1.76+); Claude Desktop does not; claude.ai web/mobile connectors do not yet.
Consequence: for THIS tier's launch audience the approval story is the folder
channel, which upgrades the Q19 push notification from nice-to-have to
near-required — a phone ping saying "approval waiting in Files" closes the
discovery gap that iCloud's lazy sync opens. The auto ladder means every client
gets the best channel it can render, and upgrades arrive without our code
changing. Watch item: MCP 2026-07-28 moves elicitation to stateless MRTR;
migration rides the SDK upgrade.

## Non-goals (v1)

- Multi-user / team access. One human, their devices, their tokens.
- Cloud persistence of anything. The Mac remains the only home of data.
- Exposing folder pipelines remotely (drop targets are already reachable via
  iCloud itself; the daemon needs no port).
- Building our own tunnel. We ride Tailscale/Cloudflare and say so.

## Milestones

- **M0 — spike:** governed server over streamable HTTP on loopback; the
  existing test suite's gate tests re-run against the HTTP transport.
  Exit: elicitation and denial behave identically over HTTP and stdio.
- **M1 — gateway: BUILT 2026-08-01.** @cortland/remote: loopback-only
  streamable-HTTP mounts for mail+context, bearer tokens (secret shown once,
  SHA-256 + metadata on disk — strictly better than Keychain-storing the
  secret, since there is nothing to steal), read/write scopes with pre-gate
  refusal + audit row, principal (`token:<id> session:<id>`) on every remote
  audit row via a new framework column, Origin-header refusal, session↔token
  binding, revocation effective mid-session, launchd on/off/status. 8 tests +
  live-verified: real mail_search over HTTP (fenced output survives the
  transport), read-token mail_mark refused before the gate with the exact
  audit row the exit criterion named. Deviation from plan: wizard step
  deferred — the CLI's own on/off/status is the onboarding for now.
- **M2 — public rung:** Funnel/Cloudflare recipe, OAuth 2.1 endpoint,
  dynamic client registration; claude.ai custom connector live test from the
  phone. Exit: the phone app searches mail from a coffee shop; a gated write
  from the same session walks the approval ladder for real.
- **M3 — hardening:** rate limits, token rotation, elicitation matrix
  documented per client, threat-model review against docs/01, public README.

## Open questions (NOTES Q24–Q26)

- Q24: OAuth implementation shape — implement the MCP auth spec in-process,
  or front with a maintained authorization-server library? (Survey first;
  hand-rolling OAuth is how products end up on incident blogs.)
- Q25: session semantics for long-lived approvals over HTTP — a gated call
  can block minutes on a human; confirm streamable HTTP session resumption
  handles that gracefully across vendor-side timeouts, or the approval must
  become async (request → poll) at the protocol edge. This may be the forcing
  function for the full async queue (Q17 v2 proper).
- Q26: which vendors render elicitation for remote connectors (the matrix).
